# Go-to-Market Plan

## Reader Promise

The reader can run a focused design-partner and product-led motion without wasting time selling a generic MCP proxy.

## Summary (≤120 words)

The initial market is not every developer using MCP. It is platform and security teams whose MCP sprawl has crossed into identity, policy and reliability pain. The acquisition wedge is an open import-and-consolidate CLI. The paid conversion wedge is managed OAuth and verified connector repair. Sales should begin with design partners, publish evidence, and expand through enterprise governance—mirroring LiteLLM's developer-to-platform path while using transparent cloud pricing like Composio.

## What We Found

## Ideal customer profile

### Primary ICP

- 200–5,000 employee software or data-intensive company;
- central AI/platform engineering team;
- 10+ MCP servers/connectors or 3+ agent clients;
- multiple human users connecting their own SaaS accounts;
- security review, audit or regulated data requirements;
- at least one production workflow where tool failure has business impact.

### Secondary ICP

Agent-product companies embedding authenticated tools for their own customers. They value white-label connection UX, tenant isolation, connector repair and predictable usage economics.

### Anti-ICP

- individual hobby users;
- teams with 1–3 stable local servers;
- buyers seeking only a catalog count;
- bespoke consulting projects with no reusable connector;
- workflows that can accept manual credentials and no central governance.

## Positioning

**Category:** open integration control plane for agents.

**Message:**
> One MCP endpoint for every agent, with verified tools, portable credentials and policy you can self-host.

**Against Composio:** managed authentication and connector reliability without a cloud-only exit.

**Against open gateways:** not just routing—verified builds, per-user auth operations and repair objectives.

**Against building:** keep control and open manifests without staffing OAuth, connector and compatibility operations.

Do not lead with “open-source Composio.” It frames the product as a clone, obscures competitors and under-explains the reliability wedge.

## Acquisition loop

1. Developer installs core.
2. CLI imports existing client configs.
3. Gateway produces a compatibility/health report.
4. Team shares config and adds per-user connections.
5. Managed auth removes OAuth/app/token toil.
6. Verified connector incidents create assurance value.
7. Security asks for SSO, approvals, audit and VPC.
8. Enterprise standardizes and contributes fixes/connectors.

## First 90-day design-partner motion

### Recruitment

Target 30 accounts from:

- teams publicly shipping agent products;
- platform engineers discussing MCP sprawl/auth;
- companies using Composio/Nango/Pipedream or open gateways;
- LiteLLM users adding MCP;
- regulated AI platform teams.

### Discovery questions

- How many clients, servers, users and connected accounts?
- Who owns OAuth app approval and token incidents?
- What broke in the last 90 days?
- How is offboarding enforced?
- What must be self-hosted?
- How long does a connector change take to detect and repair?
- Which audit evidence is required?
- What would make the organization switch from the current stack?
- Which budget owns this: platform, security, application or integration?

### Pilot offer

- consolidate up to 10 servers;
- implement 3 critical managed-auth connectors;
- publish private compatibility dashboard;
- run one read and one write workflow;
- document exit/export;
- $5K–$15K paid pilot credited toward annual contract `[inference]`.

A free pilot is acceptable only for the first one or two design partners when it buys reusable engineering and reference rights.

## PLG funnel

| Stage | Product event | Target metric `[inference]` |
|---|---|---:|
| Install | CLI runs | 100% baseline |
| Activate | First successful call within 30 minutes | >45% |
| Consolidate | 3+ upstreams behind one gateway | >25% |
| Team | 2+ principals or config shared | >15% |
| Auth | First managed connection | >8% |
| Paid | Starter/Growth conversion | 3–6% of activated orgs |
| Enterprise signal | SSO/audit/VPC request | 10–20% of paying orgs |

## Channels

- GitHub and package ecosystems;
- technical comparisons and compatibility reports;
- client/framework integrations;
- connector vendor co-marketing;
- security and platform-engineering communities;
- cloud marketplaces after repeatable annual contracts;
- migration guides from Composio and scattered configs;
- incident/postmortem-quality content, not hype.

## Sales motion

- Months 0–6: founder-led design partners.
- Months 6–12: one solutions/auth engineer before a pure SDR.
- Add account executive only after a repeatable enterprise trigger and >$500K qualified pipeline `[inference]`.
- Sell annual platform + assurance, not per-seat alone.
- Use marketplace private offers once procurement delay is observed; LiteLLM uses this channel. [S-009]

## Proof assets

1. Public open-core constitution.
2. Connector compatibility dashboard.
3. Credential portability/exit demo.
4. Threat model and supply-chain architecture.
5. Migration benchmark.
6. Per-connector status/SLO.
7. Cost calculator with observed/proposed distinction.
8. Reference architecture with LiteLLM interoperability.

## Kill criteria

Stop or pivot after 90 days if:

- fewer than 3 qualified design partners;
- managed auth is not among top two pains;
- no buyer values a repair objective;
- Obot wins the target use case with no material gap;
- a secure portable broker cannot be built without unacceptable provider constraints;
- connector support hours imply services-like margins at proposed prices.

## Confidence Notes

The GTM plan is a hypothesis. Funnel targets and pilot prices are illustrative. The ICP and trigger logic are derived from product complexity, not customer interviews.
